Find and rank helicopter landing zones in ArcGIS Pro

Give the tool an elevation model and an area. It returns ranked landing-zone candidates, the directions each can be approached from, and a map report.

HLZ Suitability Tool v0.7.0, October 2026. Allow ten minutes for the first run.

Planning aid onlyResults do not certify a landing zone. Confirm every site on recent imagery, by reconnaissance and with the aircraft operator’s performance data.

  1. Install the toolbox

    Unzip the release into a short local folder, for example C:\GIS\HLZ_Suitability_Tool_v0.7.0. Do not use OneDrive or Dropbox: syncing slows large runs and can corrupt the results.

    In ArcGIS Pro open the Catalog pane, right-click Toolboxes, choose Add Toolbox and pick toolbox\HLZ_Suitability.pyt. You should see 0. Set Up and Audit Data Folder, 1. Analyze HLZ Suitability and 2. Validate Profiles.

    Optional: run the self-test

    Open the ArcGIS Pro Python Command Prompt (a regular Anaconda Prompt has no ArcPy):

    SETUP_HLZ_ENV.bat
activate hlz
cd /d "C:\GIS\HLZ_Suitability_Tool_v0.7.0"
RUN_ALL_TESTS.bat

    Send back the single file logs\hlz_test_logs_v0.7.0.zip if anything fails.

  2. Prepare the data

    Easiest way: the data folder. Run 0. Set Up and Audit Data Folder once (location C:\GIS, name HLZ_DATA). It creates one sub-folder per input, each with a README: 
    HLZ_DATA\01_Elevation\DTM        REQUIRED     one bare-earth raster
HLZ_DATA\01_Elevation\DSM        RECOMMENDED  one surface raster
HLZ_DATA\02_Hydrology            RECOMMENDED  water polygons/lines
HLZ_DATA\03_Exclusions           optional     wetlands, built-up, restricted, hazards (polygons/lines/points)
HLZ_DATA\04_AOI                  optional     one area polygon
HLZ_DATA\05_Search_Centres       optional     points to search around
HLZ_DATA\06_Reference            not read     imagery, roads, tiles
HLZ_DATA\07_Profiles             optional     your aircraft profiles
HLZ_DATA\08_Runs                 results
HLZ_DATA\09_Audit                audit reports
HLZ_DATA\10_Obstacles            RECOMMENDED  towers, masts, wires: FAA DOF, CSV, GeoJSON, layers
    Copy your files in, then run the tool again. The audit lists what is missing or wrong (FAIL, WARN, INFO, PASS) with what to do about it, and which files the analysis will use. It reads only file headers, so it takes seconds. The report is 09_Audit\HLZ_Data_Audit_latest.html. Without ArcGIS Pro: SETUP_DATA_FOLDER.bat and AUDIT_DATA_FOLDER.bat.
    Must have
    One DTM (bare-earth elevation) raster: single band, projected coordinate system in metres, square cells. Use the native resolution, 1 m or finer. Know whether its heights are in metres or feet.
    Data that extends past your area by the approach range plus the touchdown point and ring: 1,045 m for the medium class.
    Strongly recommended
    A DSM (top of trees and buildings) from the same survey, on the same vertical datum. Without it every rating is capped at Marginal.
    An obstacle list (towers, antennas, masts, wires). Lidar surface models miss thin structures, so without a list a tower in the glide path can look clear. Use an FAA DOF file (United States), an OpenStreetMap GeoJSON, a CSV with latitude, longitude and height, or a GIS layer with a height field. Heights are above ground; an obstacle without a height is assumed to be 30 m and marked in the report.
    Water and wetland polygons or lines. A calm lake is perfectly flat, so without them it is rated as a landing zone. Ontario example: the Ontario Hydro Network Waterbody layer.
    Optional
    An area-of-interest polygon, air temperature and altimeter setting (for density altitude), a named aircraft profile.
    Aircraft classApproach rangeData needed beyond the area
    Light750 m772.5 m
    Medium1,000 m1,045 m
    Heavy1,500 m1,570 m

    Several lidar tiles? Combine them into one raster with Mosaic To New Raster first. The full specification is in Data Requirements and Compatibility.

  3. Fill in the tool

    Open 1. Analyze HLZ Suitability. Hover over the information icon next to any field, and read the GUIDANCE lines under the fields. They explain each field and change with your choices.

    FieldWhat to enter
    HLZ data folderYour HLZ_DATA folder. Empty fields below (DTM, DSM, exclusion areas, AOI, output folder) are filled from it.
    Bare-earth elevation (DTM)Your DTM. The dialog checks it at once.
    Surface model (DSM)The matching DSM.
    Area of interestA polygon. Leave empty to use the part of the map you are looking at.
    Search around a pointOptional. A point layer, or a typed MGRS or latitude, longitude, and a radius in metres. Only that circle is searched.
    Exclusion areasYour water and wetland layers: polygons (lakes), lines (rivers, streams) and/or points (a crane, a pole, a known hazard). Lines get the width set in Width given to exclusion LINES (default 10 m); points get the Radius given to exclusion POINTS (default 10 m).
    Terrain overview gridOptional, for a large area. Tick Also create a terrain overview grid and set the cell size (default 500 m). The extra layer HLZ_Overview_Grid shows, per cell, how much of the ground passes (High / Medium / Low / None), the mean slope and how many ranked candidates it holds.
    Obstacles (layers, files)Towers, masts, wires and buildings. Layers: points, lines or polygons with a height field. Files: FAA DOF (.dat), CSV or GeoJSON. Filled from 10_Obstacles when you chose a data folder. Set the height field and units under Obstacle settings only if the tool does not find them.
    Elevation (Z) unitsMeters, or Feet for many US datasets.
    Aircraft profilePick the helicopter from the list: a generic class or a named type (Canada, United States, NATO Europe). Each entry shows its landing-point and ring size, for example CH-47F: 80 m + 30 m ring; UH-72A: 25 m + 10 m ring.
    Output folder, Run nameA local folder such as C:\GIS\HLZ_runs.

    Leave the rest at its default. The dialog also shows the area, the number of tiles and the expected time.

    Sensitive work? Under Advanced, set Basemap in the HTML report to None. The default report loads map tiles from the internet, which reveals the area you look at.

  4. Run it

    Click Run. The Messages pane reports each tile and every warning as it happens. Read the warnings: they say what weakens the result, for example “No exclusion layer” or “DSM and DTM look inconsistent”.

    Cancel is safe. Run again with the same run name and the tool resumes from the last finished tile.

  5. Read the results

    The layers appear in the map as a group, and the report HLZ_Report.html opens in your browser. In the report, click an ID in the table and the map zooms to that site and shows its touchdown circle, cleared ring, approach sectors and best approach.

    New to helicopters? Hover over the ? next to each column heading, or open How to read this table. Every top site also has an In plain words sentence.

    For the pilot: click Pilot brief at the top of the report. It shows one card per site with the position, the direction to come in from, the highest obstacle and a wind helper, and it prints one site per page.

    • Highly suitable: score 80 or more, nothing limiting it.
    • Suitable: 60 to 79, or an upslope landing only.
    • Marginal: 40 to 59, a steep approach only, or no DSM.
    • Unassessed: the data does not cover the approach area.
    • Unsuitable: under 40, or every approach is blocked.

    The approach rose shows which directions work. Green sectors are clear, amber are steep, red are blocked, grey have no data. The blue arrow is the best approach, pointing into the landing zone. This site has 29 clear directions and a hill to the east.

    Always read the Main limiting factor column: a high score can hide one blocked approach.

    A purple dot on the report map is a listed obstacle (hollow = height assumed). A site with a listed obstacle close by, or in its best approach, says so in the report and the pilot brief. Obstacles that are not in your list are not seen.

    Then check the short list on recent imagery (is it really firm, dry ground?), by reconnaissance for wires and soft ground, and against the operator’s performance data.

Large areas

There is no size limit. Big areas are processed tile by tile with a steady 2.4 GB of memory, and each finished tile is saved.

These times come from a simulated area on a slow test machine, not from real data on your PC. Run the benchmark in the self-test to measure your own speed. Use the city boundary as the area of interest, give the DSM the same cell grid as the DTM, and keep everything on a local SSD.

If something goes wrong

The DTM uses a geographic coordinate system, or the cells are not square
Use Project Raster to a UTM zone in metres (EPSG 2959 for Ottawa, 2958 for Toronto), keeping the native cell size.
Every candidate is Marginal
There is no DSM, so ratings are capped. Add the matching DSM.
Top candidates are on a lake
No water layer was given, or it is old or incomplete. Add a current water polygon layer as Exclusion areas and run again.
Many candidates are Unassessed
The data stops too close to the area. The dialog names the sides that are short. Provide more data around the area.
“DSM and DTM look inconsistent”
The two rasters probably use different vertical datums or are not registered to each other. Use a DSM and DTM from the same survey. Obstacle heights are not reliable until this is fixed.
Slopes look about three times too steep or too flat
The Elevation (Z) units are wrong (feet versus metres).
The output folder is in OneDrive or Dropbox
Choose a local folder such as C:\GIS\HLZ_runs.
“Enter the search radius” or “A radius needs a centre”
A search around a point needs both a centre (a point layer, or a typed MGRS or latitude, longitude) and a radius in metres. Give both, or clear the one you do not need.
The run stopped or I pressed Cancel
Run the tool again with the same run name and the same settings. It resumes from the last finished tile.
